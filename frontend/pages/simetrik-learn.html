¿Qué es Simetrik, en una frase?

Concepto base

Simetrik es una plataforma SaaS de automatización de controles financieros: integra controles financieros, operacionales y contables en un solo lugar. Toma datos de muchas fuentes (bancos, ERPs, pasarelas), los normaliza, los cruza automáticamente, registra los asientos contables resultantes en el ERP, genera dashboards ejecutivos y entrega reportes a clientes — todo sin escribir código.

Frase oficial: "From the moment a transaction is born, until it dies in accounting". Esa es la promesa — trazabilidad completa de cada peso, de la primera ingesta al asiento contable final.

Automate / Integrations In

📥 Integrations In — cargar datos a la plataforma

El primer paso obligatorio antes de cualquier conciliación. Hay 3 formas de cargar datos, cada una con sus limitaciones.

1. Manual Upload

Click en Create Resource → opción Source → arrastrar archivo. Formatos: XLS, XLSX, CSV, TXT. Tamaño máx: 5 GB por archivo.

El layout tabular es obligatorio: sin celdas combinadas, sin filas en blanco, sin múltiples hojas. El primer archivo define el layout; si después llega uno con columna extra → status "failed", hay que crear un Source nuevo.

2. Self-Managed (Automate menu)

Para automatizar cargas. Tres tipos de conexión:

SFTP Pull — Simetrik va al directorio del cliente y extrae los archivos.
SFTP Push — El cliente envía archivos al directorio Simetrik.
S3 Pull — Conexión a un bucket Amazon S3.

Tamaño máx aumenta a 120 GB por archivo. Workflow: 1) crear conexión, 2) crear buckets (contenedor intermedio que Simetrik usa para tomar archivos y subirlos al source correspondiente).

3. Integration Services Team costo extra

Cuando las dos opciones anteriores no aplican (formatos raros, >120 GB, layouts no tabulares). El equipo establece conexiones vía APIs, web scraping, Google Cloud Services y hace parsing para adaptar la estructura. Simetrik no modifica el contenido del archivo, solo su estructura.

4 preguntas antes de cotizar: tipo de conexión · tamaño promedio · formato · layout.

El Smart Parser (un agente de IA) está siendo desarrollado para que vos mismo resuelvas casos que hoy requieren el services team. Reducirá costos y tiempos de implementación.
Cuidado con duplicados: Simetrik detecta archivos ya cargados y para el procesamiento. Como muchos clientes pagan por GB, subir duplicados consume el doble de tu storage contratado.
Conectaste vía SFTP el archivo diario de T24 con las transacciones de cajas. Simetrik lo levanta cada noche a las 23:45 y lo deja listo para el matching de la mañana.
Automate / Resources

📦 Resources — el corazón de la plataforma

Acá creás y administrás todos los recursos que componen tu solución. Click en Create Resource y elegís el tipo.

Source

Recurso base. Cada archivo cargado se asocia a su propio source. Tiene columnas del sistema (con ícono de escudo): Unique ID, fecha/hora de carga, File ID, file name, line number. Podés ocultarlas con el ícono de ojo.

Normalization (Change Format) crítico

3 pasos por columna: 1) tipo (numeric/text/date), 2) formato original (cómo viene), 3) formato deseado (cómo lo querés). Se hace una sola vez por source; archivos futuros heredan la config.

El Smart Date Format (IA) identifica automáticamente entre 500+ formatos de fecha posibles. Magia para el campo Transaction Date.

Source Union (Union of Sources) best practice

Agrupa verticalmente varias sources en un solo recurso. Las columnas deben tener el mismo tipo de info (fecha con fecha, monto con monto). La IA (AIA) sugiere automáticamente columnas que coinciden.

Por qué siempre usar Union — incluso con una sola source: si mañana cambia el layout, simplemente creás la source nueva y la sumás al Union existente. Todas las reconciliations, postings y dashboards que dependen de ese Union siguen funcionando sin reconfigurar nada.

Reconciliation — Standard vs Advanced

Standard: tipo lineal, recomendado para procesos cortos y simples. Comparación directa entre 2 sources. Tipos de cruce: 1-to-1, 1-to-N, N-to-1, N-to-N.
Advanced: tipo modular para procesos más largos/complejos. Permite encadenar múltiples sweeps independientes (mini-reconciliations) dentro del mismo recurso. Soporta: reconciliation sweep, grouping, offset.

El Smart Building Block sugiere reglas analizando ambas sources. Vos aceptás o rechazás.

Reconcilable Groups crítico antes de Advanced

Filtros guardados que aplicás sobre una source para aislar un subconjunto. Se reutilizan en reconciliations. Ej: filtrar Card Type = "Mastercard" y guardarlo como Master credit group.

Best practice: crear un grupo donde SKT ID != empty (excluyendo registros sin identificador válido).

VLOOKUP vs Enrichment by Recon

VLOOKUP: igual al de Excel. Si la fuente cambia, hay que vaciar y reprocesar todo. Servible cuando la fuente enriquecedora es estática.

Enrichment by 1-N or N-1 reconciliation: más robusto. Si cambia la fuente, solo se reprocesan las transacciones afectadas, sin tocar el histórico. Es la opción recomendada cuando la fuente puede actualizarse (ej: diccionario de tarifas renegociables).

Transformation Columns

Columnas nuevas creadas con fórmula (similar a Excel). Ej: Real Cost = Gross Amount − Net Amount · Theoretical Cost = Gross Amount × Fee Rate · Delta = Real − Theoretical.

El Smart Transformation (IA) te deja escribir en lenguaje natural lo que querés calcular y sugiere la fórmula.

Antes de cruzar nada: siempre Source Union. Cuesta lo mismo y te salva de rehacer todo cuando el cliente cambia el layout (te pasa al menos una vez por proceso).
Ejemplo Magalu: source A = junction del merchant Magalu, source B = junction de Getnet con débito + crédito. Cruzás 1-a-1 por date+amount+ID+type → 37 de 44 cruzan, 7 quedan pendientes.
Automate / Accounting

📒 Accounting — del cruce al asiento contable

Cierra el loop: traduce cada conciliación en journal entries que viajan automáticamente al ERP del cliente.

Accounting Parameters

Cargar el chart of accounts: descargás un template Simetrik, lo llenás con número de cuenta + compañía + nombre, lo subís. Una vez por workspace (o cuando cambia el catálogo).

ERP Integrations

Dos pasos: Connection (canal de comunicación con el ERP) + Structure (qué campos contienen los asientos). Dos modos de conexión:

Middleware: conector intermedio. Configurable desde Simetrik directamente. Funciona con cualquier ERP.
Standard App: conexión directa, sin intermediarios. Solo disponible para NetSuite y SAP S/4HANA. Requiere apoyo del accounting capabilities team de Simetrik.

Siempre crear primero conexión de test antes de la de production.

Accounting Model

Las reglas que Simetrik usa para llenar los campos de la estructura. Tres tipos de campos:

  • Document fields: transversales al asiento entero (fecha de generación, compañía, currency).
  • Lines: identifica débitos y créditos. Lleva accounting code, cost center, amount.
  • Header: opcional, sin impacto contable. Ej: fecha de envío del entry.

3 tipos de asientos a configurar: Normal · Cancellation (reverso del normal, pre-configurado) · Post-Siege.

El Accounting Model Assistance (IA, release abril 2026) completará varios campos automáticamente.

Generate Automation

Pantalla de configuración en 3 pasos: 1) nombre + ERP destino · 2) elegir recurso a conciliar (standard o advanced recon — sources puras necesitan convertirse en dummy recon) · 3) fecha de inicio + tipo de evento (reconciled / manually reconciled / adjusted A / adjusted B).

Parámetros avanzados: hora de envío automático, post-after-closing (día del mes hasta el cual se aceptan asientos del período anterior, ej. 3er día hábil), aprobación manual de reversals.

Un asiento contable consolida varias transacciones de la misma naturaleza/cuenta/cost center. Si después se concilia una de esas tx individualmente → partial reversal → necesita aprobación manual.
Tu cruce SERCOM produjo 1,247 matches del día. Simetrik genera 1 journal entry por cuenta contable consolidando todos. El entry sale a SAP a las 7am del día siguiente.
Automate / Analysis

📊 Analysis — dashboards y monitors

Una vez que tenés integrations, resources y reconciliations corriendo, esta sección extrae valor de toda esa data.

Custom Dashboards

Componentes combinables: pivot tables (como en Excel, con filtros y drill-down), custom tables, reconciliation status (standard/chained/advanced), KPIs individuales (reconciled amount, unreconciled amount), charts.

Monitors (4 tipos)

Conciliation Monitor: resumen consolidado de todas las reconciliations del workspace. Mismos indicadores que en cada recon (barras verde/rojo + % reconciled).
Source Monitor: estado de uploads por fecha. Archivos processed/pending/failed/empty/stopped + número de filas por día.
Bucket Monitor: equivalente al source monitor pero para buckets self-managed.
Accounting Monitor: visión consolidada del estado de balances contables.

Consolidations vs Combinations

Consolidation = une verticalmente diferentes groupings. Caso típico: cost controls de distintos adquirentes, cada uno con su grouping → un solo control consolidado.

Combination = une horizontalmente diferentes reconciliations. Caso típico: lifecycle de una transacción (Authorization → Clearing → Settlement → Anchorage), cada etapa con su recon, unidas para ver la película completa.

Vista top-down y bottom-up: arrancá del dashboard ejecutivo (qué tarjetas tienen diferencias), agregá columna de meses para detectar timing, y abrí hasta la transacción específica. O hacelo al revés para investigar un caso puntual.
Cost control: cruzaste con un fee dictionary y descubriste que solo Mastercard Credit + Mastercard Debit tienen diferencias materiales — el resto matchea perfecto con el contrato.
Automate / Data Sharing

📤 Data Sharing — extraer datos automáticamente

Última sección del menú Automate. Dos features con revenue propio (se contratan separados, no vienen activos por defecto).

Exports

Transmisión automatizada de data a destinos cloud. Solo conecta a Amazon S3 y Google Cloud Storage. Si el destino final es otro (ej. SFTP), debe pasar primero por S3/GCS.

Tipos: by event (se dispara con auto-recon, adjustment, auto-unreconcile) o recurring (frecuencia + días + hora + zona horaria + columna fecha como trigger). Formato CSV o Parquet. Tamaño máx 5 GB por archivo.

Customer Reports SFTP propio

Para distribuir reportes segmentados a cientos de clientes. Simetrik entrega exclusivamente vía su propio SFTP service (incluido sin costo extra). Formato CSV por default.

Partitioning: hasta 3 niveles jerárquicos de carpetas. Ej Amazon: nivel 1 por merchant · nivel 2 por tipo de tx · nivel 3 por mes.

Access management: cada partición de nivel 1 recibe credenciales únicas. Mismo host, distinto user+key. El cliente Simetrik (ej. Amazon) gestiona y distribuye esas credenciales a sus propios clientes.

Conexiones para conectarse al SFTP: necesitás 3 datos — host, username y private key (la descargás desde la plataforma). Usá FileZilla u otro cliente SFTP para acceder a las carpetas generadas.
Diferencia clave: Export entrega data tal cual sale de la recon · Customer Reports la segmenta por cliente automáticamente.
Automate / Solutions (Templates)

🧩 Solutions / Templates Catalog costo extra

Sección que renombra a Templates en próxima release. Permite exportar/importar configuraciones pre-hechas en JSON, y acceder a un catálogo de soluciones pre-construidas.

Generar tu propio Template

Asigná nombre · seleccioná el recurso (ej. "incoming join" reconciliation) · click Generate Template. Simetrik produce un JSON con toda la configuración (reglas, columnas, validaciones, ajustes).

Para importar: subís el JSON desde el panel derecho. La plataforma recrea el control parametrizado y listo. Solo te queda subir los archivos de data a los sources.

Templates Catalog (Solutions Catalog)

Catálogo de configuraciones diseñadas por el services team de Simetrik basadas en su experiencia de implementación. Objetivo: fast first time to value.

Ejemplo: Mastercard Controls for Acquirers. Ves los use cases incluidos (ej. clearing), revisás controles y beneficios, hacés Manage Files para ver los archivos requeridos, los subís, click Implement — la plataforma genera automáticamente todos los recursos (sources, recons, dashboards con KPIs).

Los templates no son rígidos: una vez implementado, podés usar los building blocks para customizar cualquier recurso. Es un punto de partida sólido, no una jaula.
Templates es un SBB con costo adicional. Hay que comprarlo aparte; el support team lo activa después de la compra.
Operate / Insights

🔔 Insights — alertas automáticas

Primer sub-menú del Operate. Configurás alertas que te notifican por email cuando algo se sale de los rangos esperados.

Setup básico

Indicás qué reconciliation monitorear · definís % mínimo de tx reconciliadas esperado (ej. 90%) · si cae por debajo → email. Si esperás 90% y solo se logra 85%, llega notificación automática.

Agent Factory amplio

Opciones más amplias de monitoreo. Estos agentes monitorean todos los recursos creados y notifican vía Slack, plataforma o email.

Más vale 5 alertas bien configuradas que 50 que ignorás. Definí umbrales realistas en base al histórico de los últimos 30 días.

Operate / Record Finder

🔍 Record Finder — trazar una transacción

Te permite rastrear una transacción específica hasta el source al que pertenece.

Cómo funciona

1) Seleccionás la data source · 2) ingresás el ID de la transacción · 3) Simetrik te muestra todos los recursos asociados a esa source donde aparece esa transacción.

Útil para investigaciones puntuales: "¿dónde aparece la tx LF7715101?" → ves la lista completa de recons, dashboards, groupings que la tocan.

El adoption rate de Record Finder es bajo: muchos usuarios prefieren dashboards con tablas dinámicas filtrables para el mismo tipo de tracking. No te frustres si no es tu primera opción.
Operate / Accounting Controls

⚖️ Accounting Controls — cierre contable mensual

El workflow donde se valida y certifica el cierre del período. Roles: preparer + certifier (no puede ser la misma persona).

1. Abrir período + cargar balances

Seleccionás año y mes (ej. Noviembre 2024). Click en los tres puntos del período abierto → Update Trial Balance → descargás template, llenás con saldos por cuenta, subís de nuevo.

2. Validación de balance reconocido

Por cuenta ves: beginning balance + change + ending balance. Editás Reconciled Balance con lo que reconocés con evidencia. Si el total es $16K y reconocés $15K → diferencia de $1K (6.25%).

Dos posibles explicaciones del gap: 1) el monto sí pertenece pero falta evidencia · 2) el monto está mal clasificado y requiere ajuste.

3. Support Resources (evidencia)

  • Snapshots: capturas estáticas de una reconciliation (Audit menu).
  • External files: estados de cuenta, facturas, etc.
  • Notas: comentarios del preparer cuando la evidencia es incompleta.

4. Preparer → Certifier

Preparer hace click en Ready to Certify · Certifier recibe la cuenta → revisa, lee notas, aprueba o rechaza con motivo.

Account Grouping: si varias cuentas tienen la misma naturaleza, certificás todas juntas con un solo click. Auto-certification: para cuentas que rara vez cambian (ej. fixed assets), regla automática que certifica sin pasos manuales.

El Accounting Dashboard te muestra el % de cuentas en cada estado: pending preparation · ready · rejected · certified · self-certification. Filtrá por compañía o por usuario para gestionar tu workload.
Audit / Snapshots

📸 Snapshots — fotos estáticas de reconciliations

Una reconciliation cambia continuamente porque recibe nueva info. Si querés usarla como evidencia de un período cerrado, necesitás congelarla en el tiempo.

Configuración

Configurás una vez: ej. capturar snapshot el último día de cada mes. Simetrik genera registros periódicos automáticamente (Dec 30, Nov 29, Oct 30, etc.).

El snapshot resultante es el recurso que adjuntás como evidencia en la página de validación de cuenta dentro de Accounting Controls.

Snapshot mensual + bank statement como external file + nota = evidencia blindada para auditoría.
Audit / Activity Logs

📜 Activity Logs — todo lo que pasa en la plataforma

Registro inmutable de absolutamente cada acción ejecutada en Simetrik. Sin excepción. Indispensable para SOX y auditorías externas.

Información por entry

  • Type of action — qué operación se hizo
  • Element type + name + ID — qué recurso fue afectado
  • Responsible user — quién lo hizo
  • Date and time — cuándo
  • Resource type — categoría del objeto

Desde cada registro podés ir directamente al recurso afectado, ahorrando tiempo en investigación.

Filtros

Por usuario, por ID de recurso, por fecha específica. Te permite encontrar rápido un evento sospechoso o validar operaciones normales.

Si te llaman a auditoría: filtrá por tu usuario en los últimos 30 días y ves exactamente qué tocaste. Tu defensa documentada.

Tools / Recycle Bin

🗑️ Recycle Bin — papelera de 30 días

Almacena todos los recursos eliminados. Es tu red de seguridad ante borrados accidentales.

Características clave

  • Los recursos se preservan 30 días.
  • Durante ese período podés cancelar la eliminación y restaurar.
  • Después de 30 días, la eliminación es definitiva.
  • Filtrá por tipo de recurso: sources, unions, openings, etc.
Antes de borrar algo en producción, hacé Safe Column Removal (IA, release abril 2026) para ver qué recursos quedarán impactados.
Tools / Process View

🌀 Process View — qué está corriendo ahora mismo

Información detallada de tareas en ejecución, en cola o terminadas. Tu pantalla de diagnóstico cuando algo va lento.

Datos visibles

Recurso asociado · estado/progreso · fecha/hora de ejecución · duración total.

Si un recurso lleva horas corriendo sin terminar: screenshot de esta vista + ticket de soporte con resource ID, name y duración. El support team tiene todo lo que necesita para diagnosticar.
Tools / Relationship Maps

🕸️ Relationship Maps — visualizar dependencias

Representación gráfica de cómo un recurso se conecta con otros. Te muestra qué entra y qué sale.

Ejemplo

Generás un map para la source DB Magalu → ves qué recursos están upstream (anteriores, en este caso ninguno) y downstream (posteriores, varias reconciliations).

Si elegís una reconciliation específica (ej. DB Magalu vs Credit), el map revela toda la cadena de relaciones: sources enriquecidas que la alimentan + recons posteriores que dependen de ella.

Antes de modificar una source crítica, abrí el map. Vas a ver exactamente qué se va a romper si la tocás mal. Próxima release permitirá hacer cambios desde el map mismo con IA.
Account Management

🛡️ Account Management — usuarios, roles, workspaces

Disponible solo para administradores. Acá creás workspaces, invitás usuarios y gestionás roles.

Invitar usuarios

Tab Users and Admins → botón Invite User. Ingresás emails, seleccionás workspace, definís rol (system role o custom). Una vez enviada la invitación, el usuario puede acceder.

Crear Custom Role

Tab Roles → Create New Role → nombre + recorrés las secciones de la plataforma habilitando solo los permisos deseados. Ej: permitir crear/editar Resources sin acceso a otras secciones.

Aplicá el principio de menor privilegio siempre. Cada usuario solo con los permisos que necesita para su trabajo, ni uno más.

🤖 Agentes de IA · plataforma agentic

Lo que Simetrik llama "agentic experience"

Simetrik invirtió fuerte en convertir la plataforma en predictiva y proactiva. No es solo mostrar datos; la solución anticipa necesidades, sugiere acciones y automatiza procesos. Dos iniciativas centrales: Smart Building Blocks + AI Agents y Simetrik Box (integración embebida en portales de partners). A continuación los agentes específicos.

🧠 Smart Parser

activo

Catálogo de parsers que te permite ajustar formato/layout de archivos sin pedirle al services team. Identifica los cambios necesarios y los aplica automáticamente. Cada vez tiene más opciones.

Integrations In: cargar data

3 formas: manual, self-managed, services team.

20 min · práctica
✓

Manual upload

Create Resource → Source → drag&drop. Formatos: XLS/XLSX/CSV/TXT · máx 5 GB · layout tabular obligatorio (sin merged cells, sin filas en blanco, sin multi-sheet).

Self-managed

Normalization (Change Format)

Limpiar cada columna antes de cruzar.

25 min · técnico
✓

Cada columna del source se prepara: tipo + formato original + formato deseado. Una sola vez por source; futuros archivos heredan la config.

Casos típicos

  • Transaction ID → integer sin separadores ni decimales.
  • Transaction Date → el Smart Date Format identifica entre 500+ formatos.
  • Amount → separador decimal estándar + 2 decimales máx.
  • Card number (últimos 4) → text para preservar ceros a la izquierda.

System Columns

Cada source tiene columnas del sistema con ícono de escudo: Unique ID, fecha/hora de carga, File ID, file name, line number. Ocultalas con el ícono de ojo si no las necesitás.

Source Union desde el día 1, incluso con una sola source. Cuando cambie el layout (te va a pasar), creás la source nueva, la sumás al Union, y todo lo que dependía sigue funcionando.

Tu primera Standard Reconciliation

Configurá un cruce 1-a-1 con sweeps.

30 min · práctica
✓

Pasos

  1. Automate → Resources → Create Resource → Standard Reconciliation.
  2. Elegís Source A y Source B (siempre desde un Source Union, nunca directo).
  3. Configurás el tipo de cruce: 1-1, 1-N, N-1, N-N. Para sale ↔ acquirer suele ser 1-1.
  4. Definís el sweep (bag of rules). El primer sweep con las reglas más estrictas, sin tolerancia. Sweeps siguientes con tolerancias relajadas.
  5. Reglas típicas: date == date · amount == gross_amount · id == id · tx_type == tx_type · card_type == card_type.

Tolerancias

Una compra hecha a las 23:59 que el acquirer procesa a las 00:01 genera diferencia de fecha. Sin tolerancia, no cruza. Pero cuidado: reglas muy laxas hacen "match entre manzana y pera".

Lectura de resultados

De 44 transacciones del merchant: 37 cruzaron, 7 pendientes. Filtrás solo las no reconciliadas y reducís tu workload drásticamente.

Para sweeps posteriores, considerá: amount tolerance ±0.05 (redondeo) · date tolerance ±1 día (timing). Más laxo que eso requiere autorización.

Reconcilable Groups + Enrichment

Filtros guardados, VLOOKUP, cost control.

25 min · intermedio
✓

Reconcilable Group

Filtro guardado sobre una source para aislar un subset. Aplicás filtro en Card Type = Mastercard, lo guardás como Master credit, lo reutilizás en cualquier reconciliation.

Best practice obligatoria: crear un grupo donde SKT ID != empty. Excluye registros sin identificador y previene inconsistencias.

VLOOKUP vs Enrichment

VLOOKUP — como Excel. Si la fuente cambia, vaciás y reprocesás todo (peligro con históricos cerrados).

Enrichment by 1-N or N-1 recon — solo se reprocesan las tx afectadas. Mucho más seguro. Usalo siempre que la fuente puede cambiar (ej. diccionario de fees renegociables).

Cost Control con Transformation Columns

  • Real Cost = Gross Amount − Net Amount
  • Theoretical Cost = Gross Amount × Fee Rate
  • Delta = Real Cost − Theoretical Cost

El Smart Transformation (IA) te deja escribir la lógica en natural language y sugiere la fórmula.

Después de calcular el delta, creá un grouping para verlo agregado. Vas a detectar rápido en qué tarjetas o adquirentes está el problema.

Advanced Reconciliation: sweeps, grouping, offsets

Cuando una sola recon no alcanza.

30 min · avanzado
✓

Permite encadenar múltiples sweeps independientes dentro del mismo recurso. Tres tipos de sweep:

1. Reconciliation Sweep

Mini-recon 1-a-1 dentro del recurso. Las reglas son las mismas: ID, date, amount, tx_type. Las Smart Rules (IA) sugieren las óptimas analizando ambas fuentes.

2. Grouping Sweep

Cuando una tx del merchant aparece dividida en varias líneas del acquirer. Create Aggregation con criterios: mismo date + mismo ID → suma amounts. Match: date+ID+amount+tx_type.

3. Offset Sweep

Para transacciones que se compensan dentro de la misma source. Caso típico: payment cancelado con refund. Match: date+ID+amount (no tx_type porque por definición son diferentes).

Common error: una columna no aparece al definir reglas. Posibles causas: (a) la columna no fue agregada al Source Union, (b) la columna no está enabled para la reconciliation.
Resultado típico de Advanced: merchant 70% reconciliation rate (5 matches: una parte 1-a-1, otra por grouping, 2 offsets, 3 pending) · acquirer 100% reconciliation rate.

Cierre contable: preparer + certifier

Workflow auditable de validación de balances.

25 min · workflow
✓

Apertura del período

Operate → Accounting Controls → seleccionás año + mes → Update Trial Balance → cargás template con saldos por cuenta.

Validación

Por cuenta: beginning balance + change + ending balance. Editás Reconciled Balance con el monto reconocido con evidencia. Si total $16K y reconocés $15K → gap $1K (6.25%).

Support Resources (evidencia)

  • Snapshots — capturas estáticas de reconciliations (Audit menu).
  • External files — bank statements, facturas.
  • Notas — comentarios del preparer cuando la evidencia es incompleta.

Roles separados

Preparer ≠ Certifier. Preparer arma evidencia y hace click Ready to Certify. Certifier revisa, lee notas, aprueba o rechaza con motivo.

Atajos

Account Grouping — agrupás cuentas con misma naturaleza y certificás todas con un click. Auto-certification — regla automática para cuentas que rara vez cambian (ej. fixed assets).

Cuentas con <10% de gap son normalmente OK con nota. Cuentas con >30% requieren ajuste o reclasificación — escaláselas al supervisor.

Analysis: dashboards, monitors, KPIs

Convertir data en insights ejecutivos.

20 min · análisis
✓

Custom Dashboards

Componentes: pivot tables (como Excel) · custom tables · reconciliation status · individual KPIs · charts.

4 Monitors

  • Conciliation Monitor — resumen de todas las recons del workspace.
  • Source Monitor — estado de uploads (processed/pending/failed/empty/stopped) por día.
  • Bucket Monitor — equivalente para buckets self-managed.

Consolidations vs Combinations

Consolidation: une verticalmente groupings (ej. cost controls de varios adquirentes en uno solo). Combination: une horizontalmente reconciliations (ej. Authorization → Clearing → Settlement → Anchorage, todo el lifecycle).

Hacé el top-down primero: dashboard ejecutivo → tarjetas/adquirentes con delta → drill-down hasta la tx. Te ahorra horas vs revisar fila por fila.
